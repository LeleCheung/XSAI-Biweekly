# XSAI 双周报写法笔记

## 已确认的事实

- XSAI 从 Biweekly 100 开始出现。100 期是面向项目发布的独立 `## XSAI` 长文，包含架构介绍、测试设置、性能数据和谨慎的结果解读。
- 从 101 期开始，XSAI 是 `## 近期进展` 下的 `### XSAI` 子节。这是后续常规供稿应使用的结构。
- 本地 `master` 中各期发布提交为：100 `0883979`，101 `3b5a67b`，102 `e980f3c`，103 `22ef9a1`，104 `3358abe`，105 `9bb8c18`，106 `5af4402`，107 `632b254`，108 `78f7887`。

## 常规稿的结构

常规双周报只需提供下面这一个章节；总编辑会把它放入完整双周报的“近期进展”中。类别按实际内容取用，不需要为了凑格式而补空项；在 101-108 中出现过的类别是“RTL 新特性”“Bug 修复”“代码质量”“调试工具”“评估工具”和“代码重构”。

```markdown
### XSAI

- RTL 新特性
  - 一句说明一个可验证的改动（[XSAI #123](https://github.com/OpenXiangShan/XSAI/pull/123)）
- Bug 修复
  - 修复具体模块或场景中的具体问题（[CUTE #45](https://github.com/OpenXiangShan/CUTE/pull/45)）
- 代码质量
  - 说明重构、构建或可维护性改善（[XSAI #124](https://github.com/OpenXiangShan/XSAI/pull/124)）
```

每条二级列表描述一个成果，采用“动作 + 对象 + 可理解的结果/原因”的短句。只有确实仍在推进、且对读者有价值的工作才使用“正在……”；已合入的改动必须链接到对应 PR。102、103、106、107 和 108 期表明，来自 XSAI、CUTE、HBL2、xsai-env、NEMU 或 DiffTest 的工作均可放在同一 XSAI 节，只要对 XSAI 交付直接相关。

PR 链接采用 `[仓库名 #编号](https://github.com/OpenXiangShan/仓库名/pull/编号)`。同一条对应多份 PR 时，中稿以顿号分隔链接，英文稿以逗号加空格分隔链接。不要在文字中重复 URL、PR 号或代码标识符。

中文源码遵循仓库的 Markdown 规则：中英文、中数字、数值与单位之间留空格；中文全角标点前后不额外留空格；每个段落在源码中一行；列表前后保留空行。代码标识符、指令名、寄存器名和参数名使用反引号，例如 `mtilen`、`PutFullData` 和 `AmuCtrlBuffer`。

## 中英稿流程

双周报应遵循仓库中专用的 [biweekly-translator.agent.md](../../../XiangShan-doc/.github/agents/biweekly-translator.agent.md)，不是通用文档的 Weblate 手工翻译流程。该专用规范明确以中文 `biweekly-{num}.md` 为事实来源，英文 `biweekly-{num}-en.md` 为同步目标。发布历史与此一致：101-108 的每次发布提交都同时包含对应的中文和英文双周报文件，100 期也是同次提交维护双语文件。

翻译前先检查 Git 状态和中文版 diff，只翻译新增或修改的中文片段。先查阅 [glossary.md](../../../XiangShan-doc/.github/glossary.md)，严格使用已确认术语；遇到未收录的专有名词或专业术语，暂停并请负责人确认，再补充术语表。英文应自然、简洁，但必须保持与中文对应的 Markdown 结构、空行、列表嵌套、表格行列、图片路径、链接、PR 号、数值、单位、日期和代码标识符；实际可行时中英文行数一一对应。

因此，下一期的顺序应为：先根据已合入 PR 写中文 `### XSAI`，再按该 agent 规范同步为英文；不要让英文稿成为中文内容的独立来源。
